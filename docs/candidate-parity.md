## Architecture

The Rust application service owns configuration, SQLite, microphone streams, native keyboard polling/evdev, the four-clip bounded queue, model download/verification, child supervision and the learning scheduler. A separate recording thread prevents microphone initialization from blocking key-release/cancel handling. The TypeScript webview only invokes named commands and renders state. Hiding Settings does not stop the service. Native inference runs in a persistent child of the same release executable and calls transcribe.cpp 0.3.1 through its C ABI. Every used ABI structure is checked against the loaded library's size/alignment before model loading.

Only one inference worker/model is kept loaded. Switching drops/reaps it before loading the replacement; failed switches restore the previous setting. Native GPU-load/run failure retries on CPU. Worker output uses a bounded channel and a 180-second response deadline. Unix process groups are killed on cancellation/quit; Linux also uses parent-death signalling, and the native worker monitors parent lifetime on Unix. Windows helpers start suspended, join a kill-on-close Job Object, then resume; explicit cancellation additionally uses `taskkill /T`. Native inference, optional installation and training share this ownership path. Native Windows verification is user-deferred. No transcript text enters generic timing logs. Logs rotate at 2 MB with one retained predecessor. Process stderr is suppressed; richer sanitized worker-error logging remains incomplete.

Storage lives only in `speechify-tauri-candidate` under the platform's user-data directory. `SPEECHIFY_CANDIDATE_PARENT` changes its parent for isolated tests; `SPEECHIFY_HOME` is ignored. The app identifier, tray name, autostart entries and Unix service lock are candidate-specific. Original files are never opened for writing. Import requires empty candidate history, uses SQLite's backup API, and copies referenced WAVs. Model reuse copies a GGUF after validating the catalog hash; completion uses a candidate partial file and atomic rename. Unix data directories have mode 0700. Trained-version deletion is confined to canonical paths inside candidate-owned `models/`.

## Narrow Python exceptions

The default native dictation/service/frontend never imports or launches Python. `resources/exception-worker.py` is restricted to CTranslate2 Distil/trained models and Kyutai; it loads a candidate-owned local model once and accepts only JSONL WAV requests. It owns no recording, hooks, history or settings. `resources/training/` contains the baseline trainer plus its small audio/label/metric helpers and a candidate-only configuration adapter. The adapter refuses adoption; Rust owns that decision and verifies both gates. The training script cannot resolve the installed application's home.

`resources/requirements/{whisper,transformers,training}.lock` are universal Python 3.12 hash-locked environments resolved with the same fixed 2026-10-11 cutoff. `scripts/setup-exception.py` installs them only after an explicit invocation, into separate candidate environments. Non-native model manifests pin Hugging Face commit revisions and validate LFS SHA-256 or Git blob identity before atomic directory completion. Multi-gigabyte environments and model downloads were not run during this task. This is an unverified optional path, not evidence of model/training parity.

## Most important remaining acceptance gaps

1. Actual microphone, global-input, focus/clipboard, indicator, tray and login acceptance remain lead/user work. The lead collected the baseline isolated-Xvfb window screenshot at `tauri-evidence/lead-window.png`; it is not a post-change interaction pass.
2. Replacement is limited to standard Windows Edit controls and remains runtime-untested. Linux/macOS/Wayland/browser/rich-editor replacement is refused after saving the correction.
3. Wayland automatic paste/portal integration is missing. Record in app works without global input grants and exposes Copy text; global hold still requires explicit evdev read permission. No privileges, compositor policy or installed applications are changed.
4. Eleven native catalog paths exist but only Moonshine CPU has fixture evidence. Optional Python families, GPU devices and the complete training/adoption/rollback lifecycle are untested.
5. Teacher confidence remains heuristic; native token-probability/VAD scoring and fine-grained timing instrumentation remain incomplete. Mac/Windows runtime evidence is user-deferred.


## Follow-up implementation limits (2026-10-27)

This continuation preserves the lead's local-cleanup fallback and full-dataset export fixes (`26157b2`, evidence `a38e6da`). No dependency versions or lockfiles changed. The same original Moonshine and JFK fixtures are intact.

- X11 clipboard owner is a separate crash-owned helper of the release executable, not an input hook. It snapshots supported text/image MIME targets, with 128 KiB per target and 32 MB total limits; arbitrary private targets and larger payloads refuse automatic paste. INCR transfers and clipboard-manager persistence on candidate quit remain unsupported. Restoration checks ownership under a server grab; snapshot acquisition subscribes to XFixes selection notifications and aborts on any generation change, including the same owner copying again. XFixes is required; absent support refuses automatic paste. This is implemented, not a live X11 acceptance pass.
- Windows clipboard HGLOBAL snapshots preserve Unicode/HTML/RTF and other memory-backed formats; bitmap/palette/metafile/private OS handles refuse automatic paste. The focused control is obtained from the foreground GUI thread. Helpers use suspended-start Job Objects so crash cleanup does not depend on a later taskkill call.
- macOS uses native NSPasteboard items, all available type data, and changeCount. A new identical copy increments the count. AppKit exposes no atomic compare-and-restore transaction: an external copy racing exactly between the count check and clear/write remains a hard limitation. Native Mac linking/build is handed to the lead's branch-only packaging workflow; no CI or push was added here.
- Windows replacement is deliberately narrow: a standard `Edit` control, same process/control, exact expected UTF-16 text, unchanged collapsed caret, a two-minute receipt, bounded synchronous messages, and an undoable range replacement. Browser, terminal, rich-edit and other platforms refuse safely. Separate cross-process Win32 messages are not an atomic edit transaction; concurrent programmatic target mutation is a residual limitation and native acceptance remains required.
- Record in app/Stop and transcribe use the same background capture queue and minimum-duration policy, without opening a global input source from those commands. Cancel now also cancels active capture. No microphone was opened by delegated validation. Wayland global shortcuts still need compositor/portal support or an explicit narrow evdev grant; generic portals do not establish an exact external text target for safe replacement.
- Optional setup is packaged, supervised, and visible in Models/Learning. Rust cancels its process tree, bounds progress queues and waits, serializes environment mutation against inference, and blocks training during installation. Completed environments have a marker; incomplete model directories are never installed and retry restarts their files. Python 3 and uv are explicit prerequisites; uv caches and managed Python installations are redirected into candidate data. Optional runtime/training correctness still needs real installs.
- Language and beam settings now invalidate workers that captured those values at startup. Teacher choice matches the reference NVIDIA-memory/CPU-consent policy; CUDA absence in the bundled native library may cause CPU fallback, which still requires teacher CPU consent.
