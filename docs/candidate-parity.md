## Architecture and isolation

The Electron main process owns state, shortcut configuration, inference queues, model selection, learning, tray and window lifetime. An invisible sandboxed audio service window captures only on main-process instructions, resamples with Chromium's OfflineAudioContext, and returns bounded clips. Settings is a separate sandboxed renderer, with an allowlisted main-process action dispatcher and no Node access. Closing Settings hides it; it does not stop audio or inference.

Global key input runs in a child process so a native hook failure cannot crash the service. Native ASR runs in another process with one loaded model/session. A maximum of four dictations and 120 seconds per clip are accepted. Cancellation terminates the worker tree. Native backend failures retry CPU; a process crash during inference retries the same clip once on CPU. Model files are checked against catalog SHA-256 pins on selection. Failed switches restore the previous selection and attempt to reload it.

Storage is `$XDG_DATA_HOME/speechify-electron-candidate` (default `~/.local/share/...`), `%APPDATA%/speechify-electron-candidate`, or `~/Library/Application Support/speechify-electron-candidate`. Electron userData, locks, SQLite, TOML, logs, models, HF cache and optional Python environments live there. The login entry is candidate-specific and opt-in. Explicit SQLite import uses SQLite backup, copies referenced WAVs into new candidate filenames, and preserves imported learning state in an inert namespace so imported version paths cannot be pruned. Model reuse is read-only and requires a matching catalog hash.

Generic diagnostics contain timings, process exit codes, model/device IDs, sample counts and error classes, not transcripts. Native stderr is drained without recording text because some libraries print token output. Timings rotate at 2 MB with one prior file. History and explicit fixture reports intentionally contain transcripts.

## Narrow Python exceptions

The package ships file-only Python helpers under `resources/python`. `worker.py` explicitly accepts only Kyutai 1B/2.6B, Distil-Whisper, and `ft:` trained CTranslate2 models. These have no pinned transcribe.cpp catalog artifact in the baseline. It imports only inference recipes, receives bounded audio requests, and never manages UI, hooks, recording, clipboard, settings or application lifetime. The main TypeScript service owns the process and cancellation. Transformers 5 inference and Transformers 4 training have separate hash-locked Python 3.12 environments. Downloads/caches are candidate-owned; offline inference uses `HF_HUB_OFFLINE=1`.

Fine-tuning preserves the baseline `scripts/finetune.py` evaluation/training implementation because PyTorch/PEFT/CTranslate2 conversion has no equivalent native implementation supplied by the baseline. Its support modules are staged into the package; `audio.py` is replaced by file-only WAV helpers. Main never uses `--force`, `--no-regression` or `--apply`; it independently checks both gates and verifies candidate-owned output before adoption. The replacement path is a native backend for each missing family, a GGUF conversion path for trained weights, and a separately validated native trainer; neither is disguised as completed work.

## Visual design

The contract provides the design decision: background `#151923`, surface `#202735`, raised `#2b3547`, text `#f3f6fc`, muted `#b1bed2`, accent `#8db7ff`, error `#ff9191`, success `#92d5bd`. The system sans stack uses 15 px body, 24 px heading and 13 px metadata. A 200 px sidebar anchors the five required pages; the main area uses 28 px padding. The waveform is the sole distinctive graphical element; model rows favor readable names and details over dashboard cards. History is split list/detail and reflows vertically. Controls have 40 px minimum height, 2 px keyboard focus rings and reduced-motion handling. Light mode follows system preference or explicit selection. Actual window screenshots and visual verification are pending lead/user device runs; no fake recordings are seeded.
