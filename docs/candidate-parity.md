## Architecture and isolation

The Electron main process owns state, shortcut configuration, inference queues, model selection, learning, tray and window lifetime. An invisible sandboxed audio service window captures only on main-process instructions, resamples with Chromium's OfflineAudioContext, and returns bounded clips. Settings is a separate sandboxed renderer, with an allowlisted main-process action dispatcher and no Node access. Closing Settings hides it; it does not stop audio or inference.

Global key input runs in a child process so a native hook failure cannot crash the service. Native ASR runs in another process with one loaded model/session. A maximum of four dictations and 120 seconds per clip are accepted. Cancellation terminates the worker tree. Native backend failures retry CPU; a process crash during inference retries the same clip once on CPU. Model files are checked against catalog SHA-256 pins on selection. Failed switches restore the previous selection and attempt to reload it.

Storage is `$XDG_DATA_HOME/speechify-electron-candidate` (default `~/.local/share/...`), `%APPDATA%/speechify-electron-candidate`, or `~/Library/Application Support/speechify-electron-candidate`. Electron userData, locks, SQLite, TOML, logs, models, HF cache and optional Python environments live there. The login entry is candidate-specific and opt-in. Explicit SQLite import uses SQLite backup, copies referenced WAVs into new candidate filenames, and preserves imported learning state in an inert namespace so imported version paths cannot be pruned. Model reuse is read-only and requires a matching catalog hash.

Generic diagnostics contain timings, process exit codes, model/device IDs, sample counts and error classes, not transcripts. Native stderr is drained without recording text because some libraries print token output. Timings rotate at 2 MB with one prior file. History and explicit fixture reports intentionally contain transcripts.

## Narrow Python exceptions

The package ships file-only Python helpers under `resources/python`. `worker.py` explicitly accepts only Kyutai 1B/2.6B, Distil-Whisper, and `ft:` trained CTranslate2 models. These have no pinned transcribe.cpp catalog artifact in the baseline. It imports only inference recipes, receives bounded audio requests, and never manages UI, hooks, recording, clipboard, settings or application lifetime. The main TypeScript service owns the process and cancellation. Transformers 5 inference and Transformers 4 training have separate hash-locked Python 3.12 environments. Downloads/caches are candidate-owned; offline inference uses `HF_HUB_OFFLINE=1`.

Fine-tuning preserves the baseline `scripts/finetune.py` evaluation/training implementation because PyTorch/PEFT/CTranslate2 conversion has no equivalent native implementation supplied by the baseline. Its support modules are staged into the package; `audio.py` is replaced by file-only WAV helpers. Main never uses `--force`, `--no-regression` or `--apply`; it independently checks both gates and verifies candidate-owned output before adoption. The replacement path is a native backend for each missing family, a GGUF conversion path for trained weights, and a separately validated native trainer; neither is disguised as completed work.

## Visual design

The system sans stack uses 15 px body, 24 px heading and 13 px metadata. A 200 px sidebar anchors the five required pages; the main area uses 28 px padding. The waveform is the sole distinctive graphical element; model rows favor readable names and details over dashboard cards. History is split list/detail and reflows vertically. Controls have 40 px minimum height, 2 px keyboard focus rings and reduced-motion handling. Light mode follows system preference or explicit selection. Actual window screenshots and visual verification are pending lead/user device runs; no fake recordings are seeded.

## Continuation implementation and limits

Continued from lead commit `f8826da` (implementation `95755f7` plus `f406cd3` fixes). The lead's pre-LIMIT history filters and finite-confidence validation remain covered. `continuation-tests.txt` and `continuation-packaged-tests.txt` record **33 passing Linux fixture/unit tests** under host Node and the packaged Electron runtime, including the actual compiled capture script with browser API fixtures. Those tests exposed and fixed CommonJS `exports` in sandboxed renderer/capture scripts; the build now emits browser scripts separately. No fake Node globals are supplied by the capture fixture.

Capture detaches stale audio state before asynchronous close, stops idle microphones before resampling, suppresses audio arriving after cancellation, and clears main-side capture targets after cancellation/crash. Main rejects stale queued work and late model-ready results; learning cannot interrupt active inference. Optional Python worker reload preserves queued audio and can recover a CPU process crash once. These are code/fixture checks, not microphone or OS lifecycle verification.

Optional source pins are in `desktop/electron/src/optional-pins.json`: Distil uses the actual CTranslate2 repository `Systran/faster-distil-whisper-large-v3` at `c3058b475261292e64a0412df1d2681c06260fab`; Kyutai 2.6B uses `005de8e7800698a4c9963a5ac000e185b410c2f5`; Kyutai 1B uses `98aadd47649e7ccb89d1e73a6b62bcb31d38170f`. Upstream metadata dates are 2024-03-25 and 2025-06-26. Large-file SHA-256 values come from HF LFS metadata; small files were fetched at those revisions, checked against Git blob IDs, and SHA-256 pinned. The authoritative catalog IDs and baseline source information remain unchanged. Only inference-required model/tokenizer/config files are installed. No model weights or optional environments were downloaded in this continuation.

The macOS helper holds at most eight focus snapshots (each capped at two million UTF-16 units) and one latest insertion, only in process memory. Exact AX object identity, UTF-16 selection range and full text must agree; controls without these capabilities refuse. Replacement is a single attempt, clears ownership, sets only the owned selected-text range, rechecks the focused control, and writes through that exact AX object. It never sends repeated backspaces or searches for matching text. Returning the caret to the identical state after a temporary move is not distinguishable from an unchanged state; there is no continuous target-edit observer. The helper must be built on macOS and remains unverified there.

Wayland global hold/paste remains **missing**, intentionally disabled on all compositors in this build. There is no portal session, compositor-specific focus adapter, or explicit evdev/uinput grant implementation. Merely finding `DISPLAY`/XWayland or installing an injection utility does not enable support. Manual Record/Stop and Copy remain available. No permission, compositor configuration, sandbox policy or system service was changed.
