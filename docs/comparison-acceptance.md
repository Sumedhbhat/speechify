## Architecture and safety
Tauri: Rust application backend, TypeScript frontend. Electron: TypeScript application backend and frontend. Do not wrap the Python app. Use established native inference libraries/executables (existing transcribe.cpp 0.3.1 pin and hashes are a useful starting point). A narrowly scoped Python worker is permitted ONLY where required to preserve an otherwise unsupported model or training feature; document reason, scope, packaging, process isolation, and replacement path. Never make the ordinary dictation/UI lifecycle depend on Python by default.
Recording, hooks, inference and learning belong to the background service lifetime, independent of settings windows. Explicit bounded queues, cancellation, child process tree cleanup on quit, crash recovery and CPU fallback. One active dictation model, persistent between calls, offline after installation, unload before model switch. Queue speech during loading. No fabricated transcription or mock UI presented as functionality.
App IDs org.sumedhbhat.speechify.tauri and org.sumedhbhat.speechify.electron; product names Speechify Tauri Candidate and Speechify Electron Candidate. Separate speechify-tauri-candidate / speechify-electron-candidate data, settings, logs, locks, autostart entries, artifacts. Never write into existing Speechify data/model dirs. Import is explicit and copies, including SQLite-consistent backup and referenced audio; model reuse read-only with checksum validation, candidate-owned partial downloads and atomic rename. Do not modify existing installs or services.
Read applicable instructions, frontend-design and dependency-updates skills. Pin dependencies/lockfiles and respect 14-day release age rule (security fixes excepted). No unnecessary global repo settings changes.
